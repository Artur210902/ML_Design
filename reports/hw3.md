# ДЗ3: оценка верификатора

## Данные и запуск

Использован общий Python-срез эксперимента VKR-ANTEI: 36 внедрённых уязвимостей, 74 исходные находки, 52 после объединения одинаковых file/line/CWE. Для каждой находки сохранены ответы `gemini-3.5-flash-lite` в трёх запусках. Экспорт содержит только поля для оценки; исходники, объяснения модели, адреса API и ключи в него не входят.

Ответы LLM получены ранее в VKR-ANTEI. В ДЗ3 выполнены подготовка снимка, реализация двух правил фильтрации и новый пересчёт метрик. Новых вызовов модели при воспроизведении нет. SHA-256 исходных файлов записаны в `data/hw3/provenance.json`.

Обучение весов в проекте заменено настройкой применения готовой LLM. Промпты и модель из архива использовали находки сканеров и код соответствующих файлов. Для этой работы выбраны три сравниваемых варианта:

- B0: сохранить все находки сканеров.
- B1: исключить находку при ответе `false_positive` одного запуска; остальные ответы сохраняют её. Каждый из трёх запусков оценивается отдельно.
- MVP: сохранить все High/Critical. Для остальных уровней исключить находку только при ответах `false_positive` во всех трёх запусках. Пропущенный ответ или любое расхождение сохраняет находку.

Это эксперимент с повторными ответами одной модели. Запланированные в ДЗ2 две модели и извлечение полного пути данных остаются следующим шагом. Изменение выбрано из-за наличия сопоставимых сохранённых ответов. Здесь оценивается именно правило согласования трёх ответов, а не качество второго провайдера или полнота извлечения пути.

## Предобработка и оценка

Для всех вариантов используется один список находок. Проверяем совпадение ID и полей между запусками, приводим CWE к числу, объединяем одинаковые места с одинаковым CWE. Сопоставление требует совпадения файла, CWE или заранее заданного семейства CWE и допуска по строке ±3. Сначала сопоставляем точные CWE, затем семейства; одна эталонная уязвимость учитывается один раз. Лишние находки относятся к FP. Полный эталон включает пропуски сканеров.

Метрики по CWE в JSON рассчитаны по точному CWE внутри каждого среза. В общей таблице разрешены семейства; поэтому суммы отдельных срезов могут отличаться от общей оценки.

Правила B1/MVP выбраны для исследовательского сравнения на доступном архиве. Отдельного закрытого теста и подбора на независимых проектах здесь нет. Эта оценка не используется для включения автоматического скрытия находок в пилоте.

## Результат

| Вариант | TP | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|
| B0 | 23 | 29 | 13 | 0.4423 | 0.6389 | 0.5227 |
| B1, запуск 1 | 22 | 19 | 14 | 0.5366 | 0.6111 | 0.5714 |
| B1, запуск 2 | 23 | 23 | 13 | 0.5000 | 0.6389 | 0.5610 |
| B1, запуск 3 | 23 | 22 | 13 | 0.5111 | 0.6389 | 0.5679 |
| MVP, согласование трёх запусков | 23 | 23 | 13 | 0.5000 | 0.6389 | 0.5610 |

MVP убирает 6 из 29 FP, то есть 20.7%, и сохраняет 23 TP сканеров. B1 в первом запуске теряет S06; два остальных запуска сохраняют эту уязвимость. Это основание оставить проверку спорных решений аудитором.

В `reports/hw3_metrics.json` сохранены метрики, ID найденных уязвимостей, разрезы CWE и парный bootstrap по файлам: 1000 выборок, seed=42. Интервал разности precision MVP−B0: [0.0000; 0.1336], F1: [0.0000; 0.0822]. Разность recall на всех повторных выборках равна нулю. Пересэмплирование тех же файлов не оценивает риск потерь на новых проектах. Файлы синтетического корпуса также могут иметь общие шаблоны; интервал носит диагностический характер.

Цель precision 0.84 и уменьшение FP вдвое не достигнуты. Для языков Java/JS, рабочих репозиториев и сравнения с аудитором данных в этом эксперименте нет. Пилот запускается в режиме рекомендаций.

## Время и стоимость

Архив содержит три пакетных LLM-вызова с длительностями 16.77, 16.65 и 16.67 с. Их нельзя выдавать за p95 времени проверки отдельной находки: в вызове обрабатывается группа находок, а сбор контекста и работа сканеров измерены отдельно от этого журнала.

В журнале учтены 33 591 входной и 11 771 выходной токен. Финансовый расчёт выполняется по тарифу конкретного договора: `33591 × input_price_per_million / 1000000 + 11771 × output_price_per_million / 1000000`. Актуальный тариф и фактическое списание в экспорт не включены, поэтому долларовая стоимость здесь не заявляется измеренной. MVP использует все три вызова; оценка B1 использует один из них. Повторный расчёт метрик локален и API не вызывает.

## Воспроизведение

Из корня репозитория, Python 3.12+:

```sh
python scripts/evaluate_hw3.py
python -m pytest -q
```

Для тестов: `python -m pip install -r requirements-hw3.txt`. Для нового экспорта из локального VKR-ANTEI:

```sh
python scripts/import_vkr.py /path/to/VKR-ANTEI
python scripts/evaluate_hw3.py
```

Первый запуск оценки работает без сети и API-ключей на включённом снимке. Скрипт перезаписывает только `reports/hw3_metrics.json`. Экспорт выбирает разрешённые поля явно; авторские исходники и секреты не копируются. Журнал и эталоны экспортированы из собственного учебного проекта пользователя.
